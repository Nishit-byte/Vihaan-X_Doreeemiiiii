## Project in one paragraph
VivaVoce is an adaptive spoken-plus-text technical examiner built for the Vihaan hackathon (24-hour build). A student provides a GitHub repo or research paper PDF, and VivaVoce conducts an adaptive viva climbing a 4-level Bloom's taxonomy (Recall, Comprehension, Analysis, Evaluation with live pytest sandbox verification) evaluated by a fluency-blind rubric. ## What this task did
- Fully implemented `playBase64Audio`, `speakWithBrowserTTS`, `stopAllPlayback`, and `unlockAudio` in `frontend/src/services/audioRecorder.ts` per CONTEXT §5.8 without modifying or breaking B2's push-to-talk recorder hook.
- Implemented Web Audio API playback pipeline:
  - Base64 string -> `ArrayBuffer` conversion (`base64ToArrayBuffer` handles clean base64, `data:...;base64,` prefixes, and newlines).
  - Audio decoding via `AudioContext.decodeAudioData`.
  - Node pipeline: `AudioBufferSourceNode` -> `AnalyserNode` -> `destination`.
  - Single shared `AudioContext` instance (`getSharedAudioContext()`).
  - Progress calculation `getProgress()` directly mapped to the AudioContext running clock (`(currentTime - startTime) / duration`), reaching `1.0` on natural completion and freezing on stop.
  - Level meter `getLevel()` calculating RMS amplitude (0..1) from `AnalyserNode.getByteTimeDomainData` time-domain samples, dropping to `0` when stopped/finished.
  - Enforced single playback at a time: starting any audio playback immediately stops previous playback.
  - `done` Promise always resolves cleanly on end, manual stop, or decoding error (never unhandled rejects).
- Implemented browser TTS fallback (`speakWithBrowserTTS`):
  - Intelligent voice selection (`getPreferredTTSVoice`) that prioritizes `en-IN` (Indian English voices like Prabhat/Heera), falling back to `en-US`, then any English voice, then system default.
  - Boundary progress tracking via `onboundary` event with `e.charIndex / text.length`, coupled with a smooth time-based duration estimate (~2.5 words/sec) if boundary events never fire in the browser.
  - Simulated speech amplitude level (0.08..0.85) driven by speech cadence modulation functions while speaking, immediately dropping to `0` when silent, stopped, or finished.
  - `stop()` instantly invokes `window.speechSynthesis.cancel()` and resolves `done`.
  - Chrome keep-alive guard against the 15-second speech silence bug.
  - Global utterance reference prevents garbage collection silencing speech mid-sentence.
- Implemented `unlockAudio` with auto-listening on the first `pointerdown`, `keydown`, and `touchstart` gesture on `window`, preventing "AudioContext was not allowed to start" browser warnings.
- Extended the dev harness page (`frontend/src/dev/examinerDev.tsx`):
  - Added dedicated Section 2: `🔊 Playback & Browser-TTS Debug Box (Task B3)` to the collapsible debug drawer.
  - "Play MP3 File" card featuring native file picker (`<input type="file" accept="audio/*,.mp3,.wav,.ogg,.webm">`) converting selected audio file to base64 via `blobToBase64` and playing it.
  - "🎵 Sample Chime" button that generates a pleasant in-memory 1.0s WAV audio chord chime in base64 on the fly for immediate 1-click Web Audio testing.
  - "Speak with Browser TTS" card with editable question text and a 1-click button to load the current viva turn's question into TTS.
  - Real-time `LivePlaybackLevelBar` (RMS 0..1) and `LivePlaybackProgressBar` (0 → 1) animated at 60fps via `requestAnimationFrame`.
  - Global `⏹️ Stop Playback` button and automated mid-play stop and overlap test triggers.
