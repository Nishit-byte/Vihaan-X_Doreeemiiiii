## What this task did
- Fully implemented `usePushToTalkRecorder` and `blobToBase64` in `frontend/src/services/audioRecorder.ts` exactly per CONTEXT §5.8.
- Configured `MediaRecorder` with preferred MIME type fallback order: `audio/webm;codecs=opus` -> `audio/webm` -> `audio/mp4` -> browser default.
- Implemented `start(250)` timeslice chunk recording.
- Stream lifecycle: acquires a single microphone `MediaStream` and keeps it open while mounted to eliminate repetitive permission prompts across recordings; cleanly stops all tracks and disconnects nodes on unmount.
- Connected microphone to an `AudioContext` `AnalyserNode` to calculate real-time normalized microphone amplitude (0..1) via `getInputLevel()`.
- Implemented Spacebar push-to-talk key listeners:
  - Ignores `e.repeat` to prevent re-triggering while holding.
  - Ignores keystrokes when focus is inside `input`, `textarea`, `select`, `contenteditable`, or `.monaco-editor` (checking both `e.target` and `document.activeElement`).
  - Calls `e.preventDefault()` when handled to prevent page scroll.
  - Supports `Escape` key cancellation (`cancelRecording()`).
- Handled all edge cases:
  - Spacebar released before `getUserMedia` resolves: `recordingIntentRef` ensures recorder does not get stuck recording once stream resolves.
  - Clips shorter than `minDurationMs` (default 300ms) are discarded and trigger `onTooShort()`.
  - Auto-stops recording at `maxDurationMs` (default 60000ms).
  - Permission denial sets status `'denied'`.
  - Missing browser APIs set status `'unsupported'`.
  - Used mutable refs (`optionsRef`, `statusRef`, `isRecordingRef`, `streamRef`, etc.) so event listeners never read stale state.
  - React StrictMode double-mount resilience: safely stops any stream tracks acquired if unmounted while `getUserMedia` was in flight.
- Implemented `blobToBase64` using `FileReader`, explicitly stripping the `data:...;base64,` prefix to return clean raw base64.
- Added a comprehensive "Recorder Debug" box to `frontend/src/dev/examinerDev.tsx`:
  - Live status pill badge (`idle`, `requesting-permission`, `recording`, `denied`, `unsupported`, `error`).
  - Real-time animated green level bar powered by `getInputLevel()` on `requestAnimationFrame`.
  - Interactive mouse/touch push-to-talk button.
  - Last clip inspector displaying duration (ms/s), blob size (KB and B), MIME type, and clean base64 verification.
  - Native `<audio controls>` player for immediate playback using an object URL (`URL.createObjectURL`).
  - Dedicated "Spacebar Input Test" text box to test that typing spaces does NOT trigger recording.
  - Discard notice banner when a clip is shorter than 300ms.
  - Optional "Auto-advance viva on speech release" toggle to test turn submission.

## Public interface as implemented

```typescript
export interface RecordedAudio {
  blob: Blob
  base64: string /* no data: prefix */
  mimeType: string
  durationMs: number
}

export type RecorderStatus =
  | 'idle'
  | 'requesting-permission'
  | 'recording'
  | 'denied'
  | 'unsupported'
  | 'error'

export interface UsePushToTalkRecorderOptions {
  onRecordingComplete: (rec: RecordedAudio) => void
  enabled?: boolean // default true
  bindSpacebar?: boolean // default true
  minDurationMs?: number // default 300 (shorter = discarded)
  maxDurationMs?: number // default 60000 (auto-stop)
  onTooShort?: () => void
}

export interface UsePushToTalkRecorderReturn {
  status: RecorderStatus
  isRecording: boolean
  error: string | null
  startRecording(): void
  stopRecording(): void
  cancelRecording(): void
  getInputLevel(): number /* 0..1 mic level */
}

export function usePushToTalkRecorder(
  options: UsePushToTalkRecorderOptions
): UsePushToTalkRecorderReturn

export interface AudioPlayback {
  done: Promise<void>
  stop(): void
  getLevel(): number /* 0..1 */
  getProgress(): number /* 0..1 */
}

export function playBase64Audio(
  b64: string,
  mimeType?: string /* 'audio/mpeg' */
): AudioPlayback

export function speakWithBrowserTTS(text: string): AudioPlayback

export function stopAllPlayback(): void

export function unlockAudio(): void

export function blobToBase64(blob: Blob): Promise<string>
```

### Issues found and fixed by reviewer
1. **Stuck recording if `enabled`/`bindSpacebar` turns false mid-hold**: keyup returned early on those flags, so release was ignored and the mic ran until the 60 s auto-stop. Keyup now always stops an active/pending recording.
2. **Stuck recording on window blur** (alt-tab / click outside while holding Space, so keyup never arrives): added a `blur` listener that finishes the clip.
3. **`enabled` → false did not stop an active recording**: added an effect that cancels (discards) the clip when `enabled` becomes false.
4. Dev harness: the object URL for the last clip was never revoked on unmount. Moved revocation into a `useEffect` cleanup keyed on `lastAudioUrl`.

### Non-blocking notes for later tasks
- **Two hook instances = double recording.** When B4/B6 put `usePushToTalkRecorder` inside ExaminerPanel, the dev harness's own instance will also bind Space (two MediaRecorders, two mic streams). In B6, set `bindSpacebar: false` on the debug-box instance (or drop it).
- Any focused `<input>` (including checkbox/range) blocks push-to-talk. Example: after clicking the "Auto-advance" checkbox, Space toggles it instead of recording. Consider limiting the ignore list to text-like inputs later.
- The AudioContext is created on mount (outside a gesture), so it starts `suspended`. The level meter reads 0 until the first pointerdown/keydown, which then resumes it. That's fine, just expected.
- `'denied'` is permanent for the hook's lifetime (re-granting needs a page reload). That's acceptable for the demo.
- Edge/Safari not tested manually. Edge is Chromium, so the same code path applies. Safari falls back to `audio/mp4` (or webm on 18.4+).
