## Project in one paragraph
VivaVoce is an adaptive spoken-plus-text technical viva examiner built for the Vihaan hackathon (24-hour build). A student provides a GitHub repo or research paper PDF, and VivaVoce conducts an adaptive viva climbing a 4-level Bloom's taxonomy ladder (Recall, Comprehension, Analysis, Evaluation with live pytest sandbox verification) evaluated by a fluency-blind rubric (accent and grammar receive 0% weight). M3 owns the voice pipeline: STT, TTS, latency-hiding fillers, push-to-talk browser recording, audio playback, and the reactive examiner UI panel.

2. **The Spacebar Scroll Bug Fix (Escalation Fix 2):**

     - Automatically blurred active non-text controls (like checkboxes or buttons) on Spacebar press to prevent accidental toggling.
   - **`frontend/src/components/ExaminerPanel.tsx`**:
     - In the global capturing Spacebar listener, ensured every keydown/keyup handler calls `e.preventDefault()` whenever `document.activeElement` is not an input/textarea.
     - Preserved barge-in: pressing Space while speaking immediately stops playback (`stopCurrentPlayback()`) and starts recording.

3. **Core B6 Turn-Flow Features:**
   - **Initial Turn Lifecycle**: Speaks `initialTurn` once on mount after `unlockAudio` with a React 18 StrictMode double-speak guard (`initialTurnSpokenRef`).
   - **Push-to-Talk Recording**: Spacebar or holding the `PushToTalkButton` transitions the panel to `listening`. `levelSource` dynamically routes `recorder.getInputLevel()` directly to `VoiceOrb`.
   - **Filler Audio Playback**: Releasing Space or mouse immediately transitions to `thinking`, instantly starts a random pre-cached filler audio clip (fetched once from `fillersUrl`, failure ignored silently per spec), and dispatches `onSubmitAudio`.
   - **Response Processing**: When response arrives:
     1. Stops filler playback immediately (`activeFillerRef.current?.stop()`).
     2. Pushes the turn to transcript history (`internalHistory`).
     3. Invokes `onTurn?.(nextTurn)` once.
     4. Evaluates `student_transcript` and `verdict`: if empty transcript or `verdict === 'no_answer'`, displays inline warning banner: `"Didn't catch that — try again or type"`.
     5. Evaluates `done`: if `done=true`, transitions to `done` state and displays `DoneCard` ("Viva complete" + "View report" button wired to `onRequestReport`).
     6. Speaks `audio_base64` (or browser TTS fallback via `speakWithBrowserTTS` if `audio_base64 === ""`), transitioning to `speaking`.
   - **Word-by-Word Karaoke Highlighting**: Synchronized to `AudioPlayback.getProgress()` at 60fps across `ack_text` and `question_text`. Active word highlighted in emerald (`bg-nuxt-signal/20 font-extrabold text-nuxt-signal`), spoken words bolded white, upcoming words muted, and returns to normal selectable typography when idle.
   - **Typed Answer Flow**: Full parity for `onSubmitText`: Enter sends, Shift+Enter inserts newline, triggers filler audio and submission, stops filler on response, and speaks question.
   - **Barge-in**: Pressing Space or holding PTT while in the `speaking` state immediately cuts off playback (`stopCurrentPlayback()`) and begins recording student speech.
   - **Recording Cancellation**: Pressing <kbd>Esc</kbd> cancels active recording without creating a clip and returns panel to `idle`. Pressing <kbd>Esc</kbd> during `thinking` aborts in-flight request tracking.
   - **Late Response Guard**: In-flight `requestIdRef` ensures responses arriving after cancellation or component unmount are completely ignored.
   - **Double-Submit Guard**: While in `thinking` state, Spacebar push-to-talk, mouse button presses, and text submit buttons are disabled.
   - **Submission Rejection & Retry**: When `onSubmitAudio` or `onSubmitText` rejects, displays inline error banner with 'Retry' resending the exact same recording clip or typed text.
   - **Mic Denied Handling**: If microphone access is denied (`recorder.status === 'denied'`), displays `"Microphone access denied. Text input is primary."` pill, disables PTT button, and visually promotes text fallback input.
   - **Selectability Scoping**: `select-none` scoped strictly to buttons, pills, and meters. Question text, ack text, code highlights, and transcript history remain fully selectable and copyable.

### Live-testing bug: stuck "Simulated network error" banner
Fixed in this build, and confirmed in the browser: the banner appears with Simulate Failure on. After you uncheck it, the next typed answer (or Retry) clears it and moves the turn forward. The two checkboxes stay in sync, and Space can no longer toggle a focused checkbox. Why it looked contradictory before: in the dev page, the *harness* moves the turn forward by pushing new `initialTurn`/`history` props from inside the mock submit. So the depth meter could reach L2 and L3 while the panel's own `error` state was never reset on a successful turn. This build clears `error` on every submit, on Retry and on every new turn. (The pre-fix code was never committed, so this cause is inferred from the fix and the data flow.)

### Issues found and fixed by the reviewer (~10 lines)
1. **The first reply was silenced and the panel stuck on "Speaking…"** (`ExaminerPanel.tsx`, initial-speak effect). The effect's cleanup called `stopCurrentPlayback()` on *any* `initialTurn`/`turn` prop change. When the parent pushed the new turn, it cancelled the reply that `handleTurnResponse` had just started (seen as cancel 27 ms after speak). Because `activePlaybackRef` was then null, `done` never set the panel back to idle. This affects M4's App too, which passes `turn`. Fix: the cleanup only stops the playback that this effect started (which still covers the StrictMode double-mount).
2. **Crash in M4's App when the first turn arrives** (`QuestionCard`). `useMemo` was called *after* the `if (!turn) return` early return, so going from `turn=null` (the Start Viva screen) to a real turn throws "Rendered more hooks than during the previous render". Fix: plain word-count values instead of hooks, and the unused `useMemo` import removed.
3. **`isTextInputElement` dropped `SELECT`** (`audioRecorder.ts`). CONTEXT §5.8 says Space must be ignored in select elements. Restored.

### Non-blocking notes for J1 / the team
- **Two Space listeners remain:** the hook's listener plus a redundant global capture listener in `ExaminerPanel` (the "Global Spacebar guard" effect). It is harmless in practice: one `MediaRecorder.start` per press was verified, and barge-in works through the hook alone. Removing it (about 55 lines, deletion only) was over the reviewer's fix budget. Worth deleting in J1.
- The hook now calls `preventDefault` *and blurs the focused element* on Space page-wide, even when disabled. In the full app, Space can no longer activate a focused button or checkbox anywhere (Enter still works). This trade-off is deliberate, so Space never scrolls the page; M4 should know about it.
- On release, the state goes listening, then idle for a moment (while the blob is base64-encoded), then thinking.
- Dev harness only: Esc during thinking ignores the response, but the mock has already advanced the harness props, so the turn still moves forward. Choosing "auto" after forcing a state leaves the panel in the forced state. The orb level source defaults to "fake".
- The karaoke word index shifts by one if `ack_text`/`question_text` starts with whitespace (not the case for real or mock data).
- `docs/m3/test_b3..b6.cjs` and `docs/m3/handoffs/.gitkeep` stay untracked (not part of B6's commit list).
