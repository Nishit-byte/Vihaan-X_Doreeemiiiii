# Handoff A6 — Self-test script + hardening

## Project in one paragraph
VivaVoce is a spoken-plus-text technical viva examiner built for the Vihaan hackathon (Education track). It conducts an adaptive spoken technical examination of a student based on their GitHub repository or research paper PDF, climbing a 4-level Bloom's taxonomy ladder (L1 Recall to L4 Evaluation/Mutation with live code verification) and producing a fluency-blind assessment. M3 owns the voice pipeline: low-latency Groq Whisper speech-to-text with domain vocabulary biasing, Edge-TTS audio synthesis with Indian English voices, and pre-cached audio fillers for sub-200ms audio response latency.

## What this task did
- Built `backend/voice/selftest.py` covering all core voice functions per CONTEXT §5.7 and TASKS A6.
- Implemented 15 comprehensive automated test suites executing across both synchronous and asynchronous contexts:
  1. `to_speakable` sanitization (backticks, empty parentheses, line ranges `L12-L20` / `lines 12-20` -> `lines 12 to 20`, preserving single Bloom levels like `L4 Evaluation` and `Python 3.11`, snake_case underscores to spaces, `C#`/`F#` conversion, markdown link stripping, whitespace collapsing, and 600-character length capping).
  2. `build_spoken_text` merging (acknowledgment + question clean punctuation, handling empty ack or empty question).
  3. TTS cold vs. cached latency, empty text instant bypass (< 1ms, 0 network calls), and MP3 audio frame validation.
  4. 3 concurrent `synthesize_speech` calls via `asyncio.gather` confirming parallel execution without deadlocks or audio collisions.
  5. Filler audio cache verification (validating disk MP3s `filler_1.mp3`..`filler_3.mp3` + `fillers.json`, `get_all_fillers()`, `get_filler_audio()`, and `warm_filler_cache()`).
  6. Audio format detection from raw magic bytes (WebM, WAV, Ogg, MP4, MP3 via ID3v2 and MPEG frame sync `0xFF`, unknown binary payloads, truncated headers, empty bytes).
  7. Silence and short-clip pre-flight checks (empty bytes, < 2KB payloads, synthetic silent WAV returning `""` in < 1ms with 0 API calls) and PCM16 WAV silence trimming preserving audible speech/tones with 150ms padding.
  8. Whisper hallucination filtering (dropping known silence artifacts like `"thank you for watching"`, `"subtitles by"`, `"you"`, `"."` when they form the entire transcript, while preserving them within real multi-word technical answers).
  9. End-to-end STT round-trip transcription (Edge-TTS synthesis followed by Groq Whisper transcription validating domain keyword recognition and measuring latency; cleanly skips if `GROQ_API_KEY` is unset).
  10. Bogus-key resilience (temporarily injecting an invalid key in-process, confirming it returns `""` without raising unhandled exceptions, and verifying the key is scrubbed from error logs).
  11. `voice_router` endpoint verification via `fastapi.testclient.TestClient` (`GET /health`, `GET /fillers`, `POST /speak`, `POST /transcribe` with valid, empty, and malformed base64).
  12. `dev_server` endpoint verification via `fastapi.testclient.TestClient` (`GET /api/dev/start`, `POST /api/viva/turn` with text and audio, invalid base64 validation).
  13. Synchronous wrappers (`synthesize_speech_sync` and `transcribe_audio_sync`) in standard non-async thread contexts.
  14. Windows event-loop sanity and hardening against `RuntimeError: Event loop is closed` across rapid loop creations and garbage collection cycles.
  15. Synchronous wrappers executed from inside an already running event loop (confirming worker thread dispatch without loop collision).
- Fixed Windows-specific event-loop teardown noise:
  - Hardened `backend/voice/config.py`: Added silent transport teardown protection for `_ProactorBasePipeTransport.__del__` on Windows (`nt`), preventing `RuntimeError: Event loop is closed` when unclosed socket transports are finalized during GC.
  - Hardened `backend/voice/stt_service.py`: Updated `_get_groq_client` to track the running event loop and instantiate a fresh `AsyncGroq` client if the loop changes across `asyncio.run` calls, preventing cross-loop transport reuse errors.
- Verified that `python -m voice.selftest` from `backend/` outputs a clean PASS/FAIL/SKIP table and exits with code 0 on all passes and code 1 on any failure.
