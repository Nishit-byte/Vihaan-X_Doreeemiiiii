# Handoff B1 — Frontend recon, dev harness, stubs & mock turns

## Project in one paragraph
VivaVoce is a spoken-plus-text technical viva examiner built for the Vihaan hackathon (24-hour build). A student provides a GitHub repository or research paper PDF, and VivaVoce conducts an adaptive viva climbing Bloom's cognitive taxonomy (L1 Recall -> L4 Evaluation/Mutation with sandbox pytest verification) using a fluency-blind rubric. M3 owns the voice pipeline: STT, TTS, latency-hiding fillers, push-to-talk browser recording, audio playback, and the reactive examiner UI panel.

## Public interface as implemented

### `frontend/src/services/audioRecorder.ts`
```typescript
export interface RecordedAudio {
  blob: Blob
  base64: string /* no data: prefix */
  mimeType: string
  durationMs: number
}

export type RecorderStatus =
  | 'idle'
  | 'requesting-permission'
  | 'recording'
  | 'denied'
  | 'unsupported'
  | 'error'

export interface UsePushToTalkRecorderOptions {
  onRecordingComplete: (rec: RecordedAudio) => void
  enabled?: boolean
  bindSpacebar?: boolean
  minDurationMs?: number
  maxDurationMs?: number
  onTooShort?: () => void
}

export interface UsePushToTalkRecorderReturn {
  status: RecorderStatus
  isRecording: boolean
  error: string | null
  startRecording(): void
  stopRecording(): void
  cancelRecording(): void
  getInputLevel(): number
}

export function usePushToTalkRecorder(options: UsePushToTalkRecorderOptions): UsePushToTalkRecorderReturn
export interface AudioPlayback {
  done: Promise<void>
  stop(): void
  getLevel(): number
  getProgress(): number
}

export function playBase64Audio(b64: string, mimeType?: string): AudioPlayback
export function speakWithBrowserTTS(text: string): AudioPlayback
export function stopAllPlayback(): void
export function unlockAudio(): void
export function blobToBase64(blob: Blob): Promise<string>
```

## Deviations from CONTEXT.md and why
- In `frontend/src/components/ExaminerPanel.tsx`, `ExaminerPanelProps` was extended to include optional compatibility props (`sessionId?: string | null`, `turn?: ExaminerTurnLike | null`, `history?: ExaminerTurnLike[]`, `busy?: boolean`, `onStartViva?: () => void`) and `onSubmitAudio`/`onSubmitText` were made optional.
  - *Why*: M4 merged their initial `App.tsx` shell before M3 started. `App.tsx` renders `<ExaminerPanel sessionId={...} mode={...} turn={turn} history={history} busy={busy} onTurn={onTurn} onStartViva={startViva} />`. If `ExaminerPanelProps` had strictly required `onSubmitAudio` and rejected M4's props, `npx tsc --noEmit` would fail on `App.tsx`. Since CONTEXT §3 strictly forbids M3 from editing `App.tsx` or `types/api.ts`, supporting both interfaces in `ExaminerPanelProps` preserves 100% type safety and allows both the main application and the M3 dev harness to compile without errors.
