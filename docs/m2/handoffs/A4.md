# Handoff A4 — Demo repo "studysync": build script, bundle, planted bug, challenge

## Project in one paragraph
VivaVoce is a spoken-plus-text technical viva examiner for GitHub code repositories (Mode A) and research paper PDFs (Mode B) climbing Bloom's taxonomy from recall up to live sandbox mutation fixes. M2 owns ingestion, sandbox execution, and demo reliability: parsing repositories into AST symbols and line-numbered source, calculating git-blame authorship, parsing PDFs into concept graphs and Mermaid diagrams, executing student code safely in a timeout-enforced pytest sandbox, and ensuring 100% offline demo survivability through pre-baked caches and ASGI replay middleware.

## How Shreyas works
1. Two independent parallel lanes (Lane A: Repo Intelligence, Lane B: Sandbox / Papers / Replay); lanes never wait on each other until join tasks (J1–J3).
2. Fresh chat per task; Antigravity (Gemini 3.8 Flash) builds, Claude Code (Sonnet 5.5 / Opus 5.5) reviews.
3. Prompts over terminal commands; agent executes commands directly and provides concise plain-language steps only for physical actions.
4. Every build task writes a handoff at `docs/m2/handoffs/<TASK_ID>.md`.
5. Build agents never run `git commit` or `git push`; only the Claude reviewer commits after PASS.
6. Only the Claude reviewer edits `docs/m2/STATUS.md`.
7. Strict file ownership (CONTEXT §3); touching team files is an automatic review FAIL.
8. Windows + PowerShell compatibility for all paths and commands.
9. Secrets live strictly in `backend/.env` (git-ignored); never commit keys or tokens.
10. Concept-first communication; brief grammar correction at the end if applicable.
11. Upgrade existing code instead of rewriting when real code is already present.

## What this task did
- Fully implemented `backend/demo_cache/build_sample_repo.py` to deterministically generate the offline demo repository "studysync" (a modular Python study-partner recommender with 271 lines across 7 modules):
  - Configures Git repository with strictly non-interactive environment, LF line endings (`core.autocrlf=false`, `core.eol=lf`), and deterministic dates/authors.
  - Constructs 13 commits authored across 3 fictional contributors with fixed timestamps:
    - **Aman Verma** (`aman@example.com`): 135 lines (~49.8% share).
    - **Priya Nair** (`priya@example.com`): 78 lines (~28.8% share).
    - **Rohan Gupta** (`rohan@example.com`): 58 lines (~21.4% share).
    Total shares sum exactly to 1.0000, creating an ideal empirical basis for the "wrote it vs understands it" viva examination narrative.
  - Content includes realistic Python code with complete docstrings and type annotations:
    - `models.py`: `Student` dataclass, `profile_summary`, factory function `create_student`, compatibility helper `is_suitable_partner`.
    - `similarity.py`: `cosine_similarity`, `jaccard_similarity`, `composite_similarity`.
    - `ranking.py`: `score_student_pair`, `top_k_partners`, `filter_by_min_score`, `find_mutual_partners`, `reciprocal_match_score`, `harmonic_rank_score`.
    - `data_loader.py`: `parse_student_record`, `load_sample_students`.
    - `utils/__init__.py`: utility package re-exports.
    - `utils/vector_ops.py`: `dot_product`, `vector_norm`, `normalize_vector`.
    - `cli.py`: `format_recommendations`, `main`.
  - Planted edge-case bug: `cosine_similarity` in `similarity.py` (which imports `dot_product` and `vector_norm` from sibling package `utils.vector_ops`) computes `dot / (norm_a * norm_b)` without guarding against zero-magnitude vectors, triggering an unhandled `ZeroDivisionError` on any all-zero vector.
  - Generates 4 committed offline demo assets in `backend/demo_cache/`:
    1. `sample_repo.bundle`: 7,372 bytes (7.37 KB, well below the 200 KB limit).
    2. `sample_repo_index.json`: Parsed AST metadata conforming to `RepoIndex` with `local_path=""`, `from_cache=True`, and `source_url=DEMO_REPO_URL`.
    3. `sample_repo_authors.json`: Serialized `author_map` (`dict[str, list[OwnedSymbol]]`) and `authorship_stats` (`list[AuthorStat]`).
    4. `sample_repo_challenge.json`: Complete coding challenge specification with `description`, `target_file="similarity.py"`, `function="cosine_similarity"`, `starter_code` (buggy file), `test_code` (6 pytest tests covering identical vectors, orthogonal vectors, scaled vectors, all-zero edge cases, and dimension mismatch), and `reference_solution` (guarding `if norm_a == 0.0 or norm_b == 0.0: return 0.0`).
  - Incorporated an automated self-verification step in `build_sample_repo.py` using plain pytest in an isolated temp copy: proves starter code fails (2 tests fail with `ZeroDivisionError`) and reference solution passes (all 6 tests pass).
- Implemented comprehensive test suite in `backend/tests_m2/test_a4_demo_repo.py` with 8 test cases covering artifact existence, bundle size constraint, clean git bundle cloning and commit history, `RepoIndex` loading and helper functionality, author share distributions (49.8% / 28.8% / 21.4%), challenge schema, plain pytest verification (fails on starter, passes on reference), and deterministic build idempotence across runs.
