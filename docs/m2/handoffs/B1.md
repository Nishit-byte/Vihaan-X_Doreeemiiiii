VivaVoce is a spoken-plus-text technical viva examiner for GitHub code repositories (Mode A) and research paper PDFs (Mode B) climbing Bloom's taxonomy from recall up to live sandbox mutation fixes. ## What this task did
- Implemented `execute_verification` in `backend/sandbox/sandbox_runner.py` for the `repo_root=None` path adhering to every security and robustness rule in CONTEXT §5.7.
- Scrubbed execution environment completely: built a brand-new minimal dictionary containing only necessary system paths (`PATH`, `SYSTEMROOT`, `WINDIR`, `SYSTEMDRIVE`), non-caching python flags (`PYTHONDONTWRITEBYTECODE=1`, `PYTHONIOENCODING=utf-8`), and temp directory paths for `TEMP`, `TMP`, `HOME`, and `USERPROFILE`. Never copies `os.environ` so parent API keys are not directly present in the child process's environment dictionary.
- Invoked pytest via `sys.executable -I -m pytest -q --tb=short -p no:cacheprovider --noconftest test_vivavoce_challenge.py` inside the temporary directory with a generated `pytest.ini` (`pythonpath = .`) allowing local imports without exposing global packages or `PYTHONPATH`. The `-I` flag was verified to work without issues on Python 3.13.5 Windows 11.
- Implemented process-tree cleanup via Windows Job Objects (`ctypes` bindings to `kernel32` and `ntdll`): processes are spawned with `CREATE_SUSPENDED`, assigned to a Job object configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, and resumed via `NtResumeProcess`. In a `finally` block running after every execution, `TerminateJobObject` and `CloseHandle` guarantee that child and grandchild processes are terminated regardless of whether the run passes, fails, or times out.
- Eliminated pipe EOF hangs and buffer deadlocks by redirecting subprocess stdout and stderr to temporary files in a separate directory; output memory is bounded by reading only the tail up to `SANDBOX_OUTPUT_LIMIT` (8,000 characters).
- Structured result output parsing: extracts authoritative `N passed / M failed` counts from the last summary line, catches syntax errors in student code, handles collection and import failures, and flags "no tests ran".
- Ensured `execute_verification` never raises unhandled exceptions, always returning a well-formed `SandboxResult` with `runtime_ms` populated.
- Wrote full test suite `backend/tests_m2/test_b1_sandbox.py` (14 unit tests) covering key leak prevention, passing assertions, failing assertions, syntax errors, timeout boundary compliance (returns within timeout + 2 s), termination of spawned child processes on timeout, orphan termination on passing runs, pipe-holding grandchild resilience (no false timeout), streaming 5 MB output boundedness, directory traversal rejection (`..`), collection errors, and package subdirectory imports.

## Requests for other members
- **Notes for team / Pitch / Documentation**:
  - The sandbox must always be referred to as **"sandboxed with a timeout"**, never "isolated" or "containerized".
  - **What the sandbox does NOT protect against**:
    1. The sandbox environment dictionary contains no API keys, BUT student code executes as the same OS user account as the backend server. Student code can still read the server's environment via libraries such as `psutil` (e.g. `psutil.Process().parents()[i].environ()`), read readable filesystem files (such as `backend/.env`), and initiate outbound network connections if the host has network connectivity.
    2. Student code can forge a passing verdict by printing a fake pytest summary (e.g. `1 passed in 0.01s`) and calling `os._exit(0)`.
    3. Production or public untrusted deployments require OS container isolation (Docker) or microVMs (gVisor/Firecracker).

## Known issues / TODO
- Same-user process boundaries: Because student code executes in the same user session, in-process inspection tools (like `psutil`, which is in the venv) can inspect ancestor processes.
- Forged results via early exit: Student code calling `os._exit(0)` after writing forged summary lines cannot be distinguished from pytest exiting cleanly without an external reporter plugin.
- `repo_root` copying for multi-file repositories with sibling module dependencies, `execute_verification_async`, and `warm_up_sandbox` will be implemented in Task B2.

## Fix round 1
**Fix Agent:** Gemini 3.8 Flash, 2026-11-15

### What was changed:
1. **Windows Job Object with Kill-on-Close (`backend/sandbox/sandbox_runner.py`)**:
   - Implemented Job Object management using `ctypes` (`CreateJobObjectW`, `SetInformationJobObject` with `JobObjectExtendedLimitInformation` and `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE = 0x2000`, `AssignProcessToJobObject`, `TerminateJobObject`, `CloseHandle`).
   - Addressed venv launcher race: spawned `subprocess.Popen` with `creationflags=CREATE_SUSPENDED`, assigned `proc._handle` to the Job object, and resumed with `ntdll.NtResumeProcess(proc._handle)`. Any child processes spawned by python are automatically captured into the same job.
   - Enforced unconditional cleanup in a `finally` block after every run (pass, fail, timeout, or exception) via `TerminateJobObject` and `CloseHandle` (on Windows) and `os.killpg(proc.pid, SIGKILL)` (on POSIX).
2. **File-based I/O Redirection**:
   - Replaced `subprocess.PIPE` with two temporary files (`stdout.log`, `stderr.log`) in a separate temporary directory (`vivavoce-sandbox-io-`).
   - Used `proc.wait(timeout=SANDBOX_TIMEOUT_S)`. This removes pipe EOF dependency so grandchild processes holding file descriptors cannot cause false timeouts or buffer deadlocks.
   - Implemented `_read_output_tail` to read at most the last `SANDBOX_OUTPUT_LIMIT * 4` bytes from the file end, bounding memory consumption even when student code streams 5 MB+ of output.
3. **Honest Documentation & Threat Model**:
   - Updated the handoff to state plainly that while the environment dictionary is sanitized, student code executing as the same OS user can still inspect ancestor environments via `psutil`, read local files, access the network, or forge exit codes via `os._exit(0)`.

### New tests added (`backend/tests_m2/test_b1_sandbox.py`):
- `test_orphan_killed_after_pass`: Starts a 30s background process, test passes, and verifies the orphan PID is dead within 0.5s.
- `test_pipe_holding_grandchild_no_false_timeout`: Starts a child process with `close_fds=False`, verifies the run completes in < 8s without false timeout, and the child PID is gone.
- `test_huge_output_streamed_is_bounded`: Streams 5 MB of output to stdout in a failing test; verifies `len(stdout) <= SANDBOX_OUTPUT_LIMIT` and completes well within timeout.
