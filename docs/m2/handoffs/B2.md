# Handoff B2 — Sandbox repo copy, async wrapper, warm-up

## Project in one paragraph
VivaVoce is a spoken-plus-text technical viva examiner for GitHub code repositories (Mode A) and research paper PDFs (Mode B) climbing Bloom's taxonomy from recall up to live sandbox mutation fixes. M2 owns ingestion, sandbox execution, and demo reliability: parsing repositories into AST symbols and line-numbered source, calculating git-blame authorship, parsing PDFs into concept graphs and Mermaid diagrams, running student code under pytest, sandboxed with a timeout, and ensuring 100% offline demo survivability through pre-baked caches and ASGI replay middleware.

## What this task did
- Implemented `repo_root` repository copying in `execute_verification` (`backend/sandbox/sandbox_runner.py`), preserving directory structures and package `__init__.py` files so multi-module imports and package hierarchies function seamlessly.
- Re-implemented repository file filtering locally without importing Lane A code: skips `.git`, `venv`, `.venv`, `env`, `.env`, `node_modules`, `site-packages`, `migrations`, `build`, `dist`, `__pycache__`, caches (`.pytest_cache`, `.mypy_cache`, etc.), and symlinks. Implemented a ~10 MB cumulative file size cap (`SANDBOX_COPY_MAX_BYTES = 10 * 1024 * 1024`) with warning logging.
- Preserved all of B1's security and process controls: newly constructed minimal environment dictionary without API keys, Python `-I` flag, `pytest.ini` (`pythonpath = .`), `--noconftest`, Windows Job Object with `CREATE_SUSPENDED`, `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, and unconditional `TerminateJobObject` / `CloseHandle` in `finally`, file-based output streaming with `wait(timeout=SANDBOX_TIMEOUT_S)`, and output truncation to `SANDBOX_OUTPUT_LIMIT`.
- Validated `file_path` to ensure it is relative, stays within the temporary sandbox directory, contains no `..` segments, no drive letters or leading slashes, no NUL bytes, and is not the reserved harness filename `test_vivavoce_challenge.py`. If `file_path` is an existing file, it is overwritten with `student_code`; if it is a new file, it is created inside the sandbox copy and intermediate package `__init__.py` files are ensured.
- Implemented `execute_verification_async` via `asyncio.to_thread` for non-blocking execution inside FastAPI or asynchronous event loops, supporting concurrent verifications via `asyncio.gather`.
- Implemented `warm_up_sandbox()`: executes one trivial verification pass to pre-warm python/pytest startup and Windows page caches, returning runtime in milliseconds. It catches all exceptions and never raises.
- Measured cold vs warm timings: cold run ~1027 ms, warm run ~853 ms (both well within the < 8 s threshold).
- Created comprehensive test suite `backend/tests_m2/test_b2_sandbox_repo.py` (11 tests) verifying:
  1. Correct student fix with cross-module import (`pkg.core` imports `pkg.utils.helpers`) passes.
  2. Wrong student fix fails.
  3. Student code targeting a new module inside the repo copy succeeds.
  4. Target paths outside the repo / directory traversal / absolute paths / NUL bytes are rejected.
  5. Invalid, non-existent, or file-based `repo_root` values are rejected gracefully without raising.
  6. Skip rules correctly exclude `.git`, `venv`, `__pycache__`, `node_modules`, `build`, `dist`.
  7. Copy size is bounded by the ~10 MB limit.
  8. `execute_verification_async` operates within a running asyncio event loop.
  9. Multiple `execute_verification_async` calls execute concurrently.
  10. `warm_up_sandbox()` returns < 8000 ms.
  11. `warm_up_sandbox()` never raises even when execution errors out.
